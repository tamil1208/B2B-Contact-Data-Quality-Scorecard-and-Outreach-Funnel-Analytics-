# Outreach Data Quality and Funnel Analytics

A junior data analyst project that links **contact data quality** to **outbound campaign results**: bounce, reply and meeting rates.

> **Simulated data.** Every record in this repository was generated by `src/make_data.py`. The effects (for example, one provider having worse data) were built into the simulation as assumptions. The results demonstrate the method and are not real market findings.

## The problem

Sales teams send outreach to contact lists whose quality they cannot measure. Invalid emails, wrong job titles and stale records waste sends and can hurt sender reputation. Results are also often reported as single percentages without a clear denominator, so campaigns are hard to compare.

## What this project does

1. **Cleans messy exports** (duplicates, inconsistent labels, mixed date formats, placeholder values) and measures each problem before fixing it.
2. **Scores contact data quality** by provider: valid email %, title match % and a simple quality index.
3. **Builds the campaign funnel**: sent, delivered, replied, meeting booked, with each rate's denominator stated.
4. **Tests a claim** with a chi-square test and a confidence interval (personalized vs generic campaigns).
5. **Provides SQL** (tested in SQLite) and a **Power BI** design to present the results.

## How to run

```bash
pip install -r requirements.txt
python src/make_data.py      # creates data/raw/*.csv (seeded, so results are reproducible)
python src/analysis.py       # cleans, computes KPIs and tests, writes data/processed/*.csv
python src/run_sql.py        # runs sql/queries.sql on the cleaned data
```

Query 1 in `sql/queries.sql` is a duplicate check meant for the raw table, so it returns no rows on the cleaned data.

## Data cleaning (what was found)

| Issue | Amount | Fix |
|---|---|---|
| Duplicate contact rows | 2.9% (120 rows) | Dropped by `contact_id` |
| Duplicate event rows | 40 rows | Dropped by `event_id` |
| Missing or placeholder job titles | 6.2% | Set to "Unknown" so they stay visible |
| Missing employee count | 7.6% | Filled with the median of the same industry (documented assumption) |
| Mixed date formats | about 15% of `last_verified` | Parsed into one date type |
| Inconsistent labels and spaces | provider, industry, status | Trimmed and standardised |

After cleaning: 4,000 contacts and 3,600 events, with 0 unmatched events.

## KPI definitions

| KPI | Formula | Why this denominator |
|---|---|---|
| Bounce rate | bounced / sent | Shows list quality |
| Reply rate | replies / delivered | A bounced email cannot be answered |
| Meeting rate | meetings / delivered | Same reason |
| Quality index | 50% valid email % + 50% title match % | Simple and transparent (weights are an assumption) |

## Results (simulated data)

Overall: 3,600 sends, bounce rate 12.9%, reply rate 5.0% and meeting rate 1.6% of delivered.

| Provider | Contacts | Valid email % | Title match % | Quality index | Bounce rate |
|---|---|---|---|---|---|
| Provider A | 1,606 | 79.7% | 82.8% | 81.3 | 8.1% |
| Provider B | 1,380 | 64.7% | 64.1% | 64.4 | 14.0% |
| Provider C | 1,014 | 50.6% | 47.9% | 49.3 | 18.8% |

- Invalid emails bounced 71.8% of the time, against 1.4% for valid emails.
- Personalized campaigns had a reply rate about 2.6 percentage points higher (95% CI 1.1 to 4.1, chi-square p = 0.001).
- Contacts with a matching job title replied more often (chi-square p = 0.028).

## Limitations

- The data is simulated, and the effects were assumptions in the simulation.
- Campaigns were not randomised, so the personalization lift does not prove cause.
- Each campaign sent 300 emails, so single-campaign rates are noisy. For example, only about 137 of the 485 invalid-email sends were delivered, so that group's reply rate is unreliable.
- The quality index weights are a choice that a real team would agree on.
